Test rig: ThinkPad T14P Gen3 · Intel Core Ultra 9 285H · 64GB 6400MHz · Intel Arc 140T. Real-world results vary with hardware and files.

Lighter encryption (RC4 / ZipCrypto — designs without heavy key-derivation iterations) benefits most from GPU parallelism: hundreds to thousands of times faster. Formats with iterated KDFs (Agile SHA-512 with 100k rounds, RAR5 PBKDF2) gain roughly 2–36×, yet still beat CPU across the board. GPU acceleration relies on the optional, user-supplied hashcat component.

Sound familiar?

A forgotten password doesn't mean a lost file. Every PassGone feature exists because of one of these situations.

You remember "roughly" the words

Fragments of memory don't spell a password

Passwords from different eras blur together; typing guesses one by one eats an entire afternoon.

Import txt / csv dictionaries (one password per line); multiple dictionaries are de-duplicated and merged automatically.

You know the parts, not the order

Name + birthday + digits, a thousand permutations

You recall which pieces the password was built from, but not the arrangement.

Tick upper/lowercase / digits / symbols, define a custom character set and a length range — candidates are generated for you.

Hundreds of thousands of candidates, halfway done, time to shut down

Tomorrow it all starts over

Long recovery runs fear interruption most; rerunning means waiting twice.

Progress is tracked per file fingerprint (chunk-level); restart and it resumes automatically, never retrying what's done.

Many files, each one slow

Watching a progress bar with no end

Encrypted files try one after another, too slowly to trust.

Multi-process parallelism across all CPU cores, with live speed and estimated time remaining.

CPU too slow to wait

Strong encryption grinds a CPU down

Modern Office encryption uses high iteration counts; a CPU alone tries too few per second.

Enable GPU acceleration with one click (optional hashcat component) — up to tens of times faster on all Office formats.

The same file copied around

Duplicates run twice

Multiple copies of the same document get added and cracked separately — wasted computing.

Content hashing identifies duplicates, merges them into one record, and shares the recovered result.
